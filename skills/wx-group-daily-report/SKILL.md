# 微信群增量消息整理 + 飞书推送（每日 06:00 调度）

本 skill 服务于投资/FA 机构工作群的情报整理。**目标群不硬编码**：以 `F:\dev\wx-group-collector\config.json` 的 `groups` 数组为准（每次运行时现读，用户可能随时改监听对象）。数据由该采集器产出，交付到本地 md + 飞书云空间。

**口径核心：增量而非自然天。** 采集按自然天分文件，但消息常在零点后仍在同步，分析必须以"上次处理到哪"（检查点）为界，跨文件拼接增量。

## 流程总览（按序执行）

1. **读检查点** `state.json`（与 SKILL.md 同目录）：`{"last_run": iso, "files": {"messages-YYYY-MM-DD.jsonl": 已处理行数}}`。
2. **收集增量**：先读 `F:\dev\wx-group-collector\config.json` 的 `groups` 数组确定目标群（当前监听名单），再列出 `data\messages-*.jsonl`（按文件名日期升序），每个文件只取第 `已处理行数+1` 行起的新行，并**只保留 `group` 字段 ∈ groups 名单的行**（文件里可能混有历史监听群的消息，直接过滤掉；不因名单外的群产生任何输出）。分析窗口 = `[last_run, now]`（首次运行取最近一个自然天文件全量）。解析规则见 [references/data-format.md](references/data-format.md)。
   - **产物命名**：仅 1 个目标群 → `今日报告-YYYY-MM-DD.md` / `机构结构化表格-YYYY-MM-DD.md`，报告标题 `# <群名> · YYYY-MM-DD 日报`；≥2 个目标群 → 每群一套产物，文件名插入群名（`今日报告-<群名>-YYYY-MM-DD.md`），全部推到同一个日期目录，报告各自独立。检查点按文件行数计，与群无关（换监听群不影响增量连续性）。
   - **关联文件必须溯源**：增量中出现"文件"形态消息时，按 data-format.md 查 ±1 天 files-index 并读 `copied_to` 本体——业务文件（纪要/BP/融资材料等）的内容要并入报告相应章节，不只是列文件名；测试文件过滤；查不到索引的注明"需重传"。图片消息(2026-11-24 起)：记录自带 `image_path`、或按 `msg_iso` 查 files-index 的 `decoded_to` 得到可读 PNG——**必须视觉读图**，把图片内容摘要并入报告相应章节；仅加密 .dat 可查时在附注计数(不可读)。视频/动画表情仍为占位,忽略。
3. **增量为空**（没有新行）：仍生成**占位报告**并照常推送，保证飞书目录每日连续。占位报告 = `今日报告-YYYY-MM-DD.md`，内容为：窗口起止、"本窗口无新增聊天消息"、上一条已处理消息的时间戳（供人工核对采集器是否停摆，若上一条消息距今已超 24h 需在汇报中提醒用户检查采集器）、下一班时间。**机构表格跳过**（无数据不建空表），占位报告中注明"机构表格因无新增未生成"。目录创建、推送、检查点推进与正常流程一致。
4. **整理两份产物**（格式见下），报告日期 = **运行日**（早 6 点跑，归纳的是昨晚以来的消息；窗口起止在报告头部写明绝对时间）。
5. **本地落盘**到当前工作区：`今日报告-YYYY-MM-DD.md`、`机构结构化表格-YYYY-MM-DD.md`（YYYY-MM-DD = 运行日）。
6. **推飞书**：见 [references/feishu-push.md](references/feishu-push.md)；目录按运行日挂 `群消息整理/YYYY-MM/YYYY-MM-DD/`。
7. **更新 state.json**：写入本次各文件已处理行数与 last_run（**推送成功后再更新**；推送失败时保留旧检查点并在汇报中说明，下次重跑该窗口）。
8. **汇报**：窗口、消息条数、本地文件路径、飞书链接、机构记录数、采集器体检结果。

## 第 0 步：采集器体检（每次运行先做，06:00 无人值守必做）

直调 ps1（**禁用 check.bat——带 pause 会卡死自动化**）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File F:\dev\wx-group-collector\check-status.ps1
```

| 体检结果 | 判断与处置（无人值守） |
|---|---|
| 全部 [OK] | 正常继续；汇报里带一句"采集器体检全绿，最后消息 X 分钟前" |
| 某组件 [X]/[!]，但微信+群窗口 [OK] | 只重启该组件（命令见下），不动微信，重启后在汇报中注明 |
| 微信没开 | 无法无人值守修复（不能扫码）→ **汇报置顶提醒**用户人工开微信并跑 start.bat |
| 群窗口 [X] | 重启 collector（它会自己重开群窗口） |
| 报"未找到目标聊天" | config.json 群名与微信不一致/换账号后不在该群 → 汇报提醒核对 |
| 全部正常但最后消息 >24h | 查 `F:\dev\wx-group-collector\logs\collector.log` 末尾：仍有约 20 秒一条"已刷新消息列表引用"= 群安静；停更 = 监听循环死亡 → 重启 collector |

**组件单独重启**（把 `collector.py` 换成对应脚本名即可重启其他组件；恢复监听不动微信）：

```
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Where-Object {$_.CommandLine -match 'collector\.py\s*$'} | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }; Start-Sleep 1; Start-Process -FilePath 'F:\dev\wx-group-collector\.venv\Scripts\python.exe' -ArgumentList 'collector.py' -WorkingDirectory 'F:\dev\wx-group-collector' -WindowStyle Hidden"
```

**无人值守红线**：绝不自动运行 `start.bat`（它会重启微信并自动点"进入微信"，失败即停在登录页等扫码，必须人工）。python 进程成对出现（uv venv 跳板器+解释器）属正常，勿误判重复。

## 产物一：今日报告

文件名 `今日报告-YYYY-MM-DD.md`（运行日），结构固定：

```markdown
# <群名> · YYYY-MM-DD 日报（窗口：D-1 06:00 → D 06:00）
> 数据来源 + 口径说明（增量窗口、补报批次说明、无发送者声明、is_at_me 情况、过滤声明）

## 一、投资机构动态        ← 表格：机构 | 今日信息 | 信息源（群内讨论/合并转发/新闻转发）
## 二、项目信息            ← 按项目分小节（A/B/C…），重点项目标 ⭐；含团队/模式/融资/节奏
## 三、生态资源            ← 算力、云补贴、孵化器等非机构非项目的资源线索
## 四、行业资讯（群内转发）← 新闻链接摘要，编号列表
## 五、待办事项            ← 表格：# | 待办 | 相关人 | 时间
## 附：群文件（投资相关）  ← 注明未下载成功的文件
```

写作规则：
- **绝不虚构发言人**。人物归属只允许两种来源：@ 提及（"相关人"列用被 @ 的人）和合并转发里的 `昵称: ` 前缀。其余一律写"群内讨论"或不写主语。
- 待办的"相关人"宁缺毋滥；时间用相对表述（周六晚/下周）并附推导出的绝对日期。
- 涉密/保密内容照实标注（如"具体保密"），不要追问展开。
- 增量窗口可能横跨两天：跨窗口的对话（如昨晚开始今晨继续的话题）合并成一个话题呈现，不要拆成两半。

## 产物二：机构结构化表格

文件名 `机构结构化表格-YYYY-MM-DD.md`（运行日）。表头固定 10 列 = 群内确认的 9 字段 + 补充列：

```
机构 | 机构背景 | 基金情况 | 基金规模 | 内部分工 | 汇报线 | 投资方向 | 最近投的项目 | 谁投的 | 今日群内动态（补充）
```

- **未提及处如实标注"未提及"，禁止用模型内部知识补全**（群内明确认可口径：消息"有的有，有的没有"）。不适用填"—"（如 FA 行的投资字段）。例外:Web 检索核验到的公开信息可以补进字段,但必须标 🔍 并注明来源与时间(如 `🔍约30亿·红杉领投·2025-12·公开报道`),与群内口径明确区分;检索不到就不补,不硬凑。
- 新闻转发得来的机构信息标 `＊`。
- 同一项目的多轮资方各占一行，"最近投的项目"写清轮次。
- 本表只含**本窗口内出现**的机构（每日独立成表，不做跨日累积；如需累积版多维表格另行确认）。
- md 文件末尾附备注：数据来源、口径、与结构化 agent schema 的关系。

## 过滤规则（与投资无关的内容）

**保留**：机构信息/人事、项目进展/融资、待办、生态资源（算力/云/孵化）、新闻链接、可辨人物线索（合并转发）。
**丢弃**：采集器测试消息（"测试语音"/`语音N"秒`无实义/poc/文件传输测试/"11"/"111"）、吃饭闲聊、玩笑表情、支付消息、发票报销等行政琐事。
**边缘判断**：内部方法论讨论（如项目 S/A/B 评级）一句话带过；公众号发文安排归入待办。

## Web 检索核验与扩充（可选增强）

工具:运行会话内置 `WebSearch`(联网搜索)与 `WebFetch`(抓 URL 读原文);若会话没有这两个工具,跳过本节并在汇报注明。

三个用途:
1. **新闻链接读原文**:「链接」「合并转发」里的 URL 用 WebFetch 抓正文,"行业资讯"写内容摘要而非只转述标题;抓取失败(反爬/超时/需登录)退回标题摘要并注明"原文未抓到"。
2. **关键事实核验**:群内的融资轮次/金额/估值/机构人事动作等用 WebSearch 核验——一致 → 报告标"已核验";有出入 → 群内口径与公开报道**并列呈现**,注明差异;查不到 → 照常写群内口径,不硬凑。
3. **机构/项目背景扩充**:图片(PPT/名单截图)与文件里识别出的机构,可检索补充公开背景进机构表格或"投资机构动态",信息标 🔍 注明来源。

红线:
- **涉密内容不检索**:带保密标注的内容照实标注,绝不拆成关键词去搜;人名不与敏感推测组合检索。
- **群内口径优先**:检索结果只做核验与补充,不覆盖群内说法;冲突时两边并列,让读报告的人自己判断。
- **无人值守预算**:每班次 WebSearch+WebFetch 合计 ≤10 次,单次约 30 秒超时即放弃并注明,不得反复重试拖垮班次;检索放在产物整理阶段最后做,先保证无网也能出完整产物。

## 飞书推送要点（细节见 references/feishu-push.md）

- CLI 调用必须用 node 直调入口（Git Bash shim 有 bug）。
- 目录挂运行日：`群消息整理/YYYY-MM/YYYY-MM-DD/`；**建目录前先查 references/feishu-push.md 的 token 注册表**，已存在勿重复创建；新建后把 token 追加进注册表。
- 报告 md → `drive +import --type docx`；机构表 CSV（utf-8-sig BOM）→ `--type bitable`。同一目录串行导入。
- 推完用 `base +record-list` 验证记录数后向用户汇报链接。

## 调度（每日 06:00）

- 本工作区已配置每日 06:00 的自动化（CronCreate `0 6 * * *`），提示词直接指路本 SKILL.md。自动化无人值守：**不要向用户提问**，拿不准的就按默认规则处理并在汇报里注明假设。
- 授权失效处理（无人值守时不能走浏览器 Device Flow）：只完成本地 md 产物 + 保留旧检查点（state.json 不更新 files 行数之外……见第 7 步：推送失败不推进检查点），汇报中说明"飞书推送失败+需重新授权"，等用户下次交互时重走授权。
- 用户白天手动说"整理一下"也是本流程：从上次检查点跑到当前时刻，跑完同样推进检查点（与 06:00 调度互补，不重复不遗漏）。
